# CampusHelp — Quality Assurance Plan

**Project type:** Individual, browser-based demonstration. **Owner:** Muhammadzayniddinov.

## Quality objectives
1. All six mandatory system capabilities are demonstrable or clearly described.
2. Required request fields reject invalid submissions; tracking IDs are unique for practical demo use.
3. Request assignment, status changes and counts update consistently in local browser storage.
4. UI identifies mock/simulated functionality and does not claim to support production authentication or real email delivery.
5. Each completed GitHub Issue links real file, commit, PR or verification evidence.

## Reviews
- Requirements and wireframe consistency check before prototype implementation.
- Manual design/functional review before testing.
- Final verification against issues, milestone descriptions and report checklist.
- Individual work will not be misrepresented as peer review.

## Test procedure
1. Use a current browser with localStorage available.
2. Use **fictional** student IDs.
3. Execute six or more tests with steps, expected result and actual observation.
4. If a test cannot be run, record **Not Run**, not Pass.
5. Log defects as GitHub Issues and rerun affected tests.

## Exit criteria
Required deliverables are committed; at least six tests have actual recorded results; limitations documented; final GitHub links and authentic screenshots inserted into final report. Open work is explicitly disclosed.
